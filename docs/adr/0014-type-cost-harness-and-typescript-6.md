# ADR 0014 — Type-cost harness and TypeScript 6.0 as a development dependency

- Date: 2026-10-19
- Status: accepted (by the owner, 2026-10-19, on the recommendation)

## Context

ARCHITECTURE.md §8 sets a type-cost budget: a generated reference project of about 2,000 files that uses the public types (`Path<T>`, schema and form inference), measured through `--extendedDiagnostics` (check time, instantiations, memory), at most +10 % check time against the same project without the library, and a ceiling of instantiations per public type. ADR 0006 promises the declarations work under TypeScript 6.0 and 7.x, with and without `exactOptionalPropertyTypes`, and announced that `@typescript/typescript6` would become a development dependency when the type harnesses are built, justified by their own record. This is that record.

Facts read on 2026-10-19 from the npm registry:

- `typescript` 6.0.3 (2026-04-16) is the last JavaScript-based compiler and the last 6.x release; `typescript` `latest` is 7.0.2, `next` is a 7.1 nightly.
- `@typescript/typescript6` 6.0.2 (last published 2026-07-06, Apache-2.0, same seven maintainers as `typescript`) is a wrapper of 10,548 bytes: it depends on `@typescript/old`, an alias `npm:typescript@^6`, re-exports its compiler API (`main` `./lib/typescript.js`, `types` `./lib/typescript.d.ts`) and installs its command as `tsc6`, so it sits beside `typescript` 7 without touching `tsc`.
- TypeScript 6.0 accepts every compiler option of the repository: `tsc6 -p tsconfig.json --noEmit` checks the scripts and the testing package with no error.

Three questions follow: whether to check under TypeScript 6.0 at all, through which package, and what the gate measures under each compiler.

## Options

1. **Do nothing: TypeScript 7 only.** No byte added. The promise of ADR 0006 to Angular users, who stay on 6.0 while Angular template tooling does, becomes untested: a type that compiles under 7 and fails, or explodes, under 6.0 would ship. Rejected while ADR 0006 stands.
2. **`@typescript/typescript6` 6.0.2**, exact version, in the root `devDependencies`. 2 packages, its compiler under `tsc6`. Kept.
3. **An npm alias of the compiler itself**, `"typescript6": "npm:typescript@6.0.3"`. 1 package, 11,048 bytes fewer. But the aliased package still declares the `tsc` and `tsserver` commands, the same names as `typescript` 7: which compiler `node_modules/.bin/tsc` runs would depend on link order. Rejected: an ambiguous `tsc` in the gate costs more than 11 kB.
4. **Download TypeScript 6.0 on demand** (`npx`, a cache outside the lock file). Rejected: a network call and a package outside the lock, its licence and sources checks, inside the gate.
5. **Run the TypeScript 6.0 check only in a separate CI job.** The same package must be installed for the job, so the same bytes enter the lock; a regression would show only after the push. Rejected: the gate is the place where a type that fails under 6.0 must be refused.

## Measurements

On 2026-10-19, Ubuntu 26.04 x64, 20 logical processors, Node 24.21.0, npm 11.19.0, a machine under load from other work (load average 5.5 to 6.1), seven interleaved passes per configuration:

- **Installed size** (`npm install --ignore-scripts --save-exact` in an empty folder, `du -sb node_modules`): option 2, 2 packages, 24,358,478 bytes; option 3, 1 package, 24,347,430 bytes. `npm audit`: 0 vulnerability; `npm audit signatures`: 2 packages with verified registry signatures. No install script. The development footprint grows from 71,504,262 to about 95.9 MB (+34 %).
- **Probe project**, generated by a throwaway script: 2,000 files, each with an interface of nested objects and arrays, a function, and an import of a model ten files earlier; the "library" variant adds a local declaration file with a bounded `Path<T>` (depth 5) and a schema inference (`object`, `array`, `optional`), then in each file a schema of eleven fields, its inferred type and four `get(value, path)` calls. `--noEmit`, `strict`, `noUncheckedIndexedAccess`, `skipLibCheck`, `types: []`.

|---|---|---|---|---|
| 7.0.2, without the library, on | 0.033 s (0.029–0.044) | 0.109 s (0.097–0.137) | 8,000 | 107 MB |
| 7.0.2, with the library, on | 0.414 s (0.398–0.460) | 0.510 s (0.500–0.577) | 1,779,120 | 315 MB |
| 7.0.2, with the library, off | 0.425 s (0.417–0.465) | 0.529 s (0.516–0.552) | 1,779,120 | 315 MB |
| 6.0.3, without the library, on | 0.260 s (0.230–0.270) | 0.590 s (0.550–0.650) | 8,000 | 174 MB |
| 6.0.3, with the library, on | 2.420 s (2.350–2.590) | 2.880 s (2.800–3.060) | 1,596,054 | 594 MB |
| 6.0.3, with the library, off | 2.500 s (2.390–2.850) | 2.970 s (2.910–3.360) | 1,596,054 | 594 MB |

- **Determinism**: the instantiation count is the same in the seven passes of every configuration, under both compilers. It is not the same across compilers (1,596,054 under 6.0.3, 1,779,120 under 7.0.2 for the same project): a ceiling holds for one compiler only.
- **Time**: on the same project TypeScript 6.0 checks 5.8 times slower than 7 and uses 1.9 times its memory. The spread of check time between passes, measured from the fastest one, reaches 16 % under 7 (0.398 to 0.460 s) and 19 % under 6.0 (2.390 to 2.850 s) on this loaded machine: wider than the +10 % budget, so time cannot be judged on one pass.
- The probe's ratio of "with" to "without" is not a calibration: its library part is intensive by construction. Calibration is the harness's work.

## Decision

Option 2, under these rules.

- **The dependency**: `@typescript/typescript6` at exactly 6.0.2 in the root `devDependencies`, reached only by the type-cost harness and the type tests, under its `tsc6` command or its module; no package of the workspace depends on it.
- **What the gate measures**: under both compilers, with and without `exactOptionalPropertyTypes`, the instantiation count of the reference project and of one fixture per public type; these counts are deterministic, so one pass suffices and any count above its ceiling fails the gate. Ceilings are written per compiler in one versioned file under `bench/types/`.
- **What the gate times**: check time under TypeScript 7, with and without the library, judged on the median of five interleaved passes, with the minimum and maximum printed. Check time under 6.0 is printed by the gate but not judged: its instantiation count is the blocking signal there. Judging it on five passes would cost about 17 s on the probe, against about 7 s for one pass per configuration.
- **The explosive type**: a fixture with unbounded recursion, kept in the harness tests, must fail the ceiling under both compilers, so a harness that stops counting is seen.
- **ADR 0012, re-examined as its review condition requires**: kept. Reading the tags through the stable 6.0 API would now cost no byte and remove the known break of 7.1 (`updateSnapshot` made private), but it would read with a compiler other than the one that builds the packages, add about 0.23 s to every gate (0.38 s measured for 6.0 against 0.15 s, ADR 0012), and tie the checker to the line that ADR 0006 will drop first. The upgrade that breaks the adapter chooses then between repairing it and moving it to the 6.0 API, through a record that supersedes ADR 0012.

## Consequences

- One development dependency, 2 lock entries, about 24.4 MB installed, Apache-2.0, maintained by the TypeScript team.
- The gate gains one step. On the probe: four 6.0 checks (about 7 s) and twelve 7 checks (five timed passes with and without the library, plus one pass each without `exactOptionalPropertyTypes`: about 3.7 s), so about 11 s added to a gate of 7.6 s; while the packages have few public types, the reference project is lighter and the step is shorter. The figures are measured again when the step lands and when a public type enters it.
- Public types are written for both compilers: a feature missing in 6.0 cannot be used, as ADR 0006 already said.
- When ADR 0006 drops TypeScript 6.0, the dependency and its ceilings leave in the same change.

## Review condition

ADR 0006 dropping TypeScript 6.0; a TypeScript 6.0 release outside the wrapper, or the wrapper deprecated; the 6.0 checks taking more than 10 s of the gate; TypeScript 7 publishing a stable compiler API (which also reopens ADR 0012).

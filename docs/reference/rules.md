### `Rule`

A type.

A rule across values: what it reads, where it can mark, and what it says of given values. It holds no state, and an application can write its own: `assertDeclaredReads` then says whether `reads` tells the truth.

```ts
export interface Rule {
    /** What the rule reads. A path covers what is under it; `anyElement` stands for every element of a list. */
    readonly reads: readonly Path[];
    /** Where the rule can place an issue, `rules.too_many_issues` aside; `anyElement` as in `reads`. */
    readonly targets: readonly Path[];
    /** The issues of these values, every one on a target; none when the rule holds. */
    readonly check: (values: unknown) => readonly Issue[];
    /** The fields these values require: a blank one among them gets an issue. A rule without it requires none. */
    readonly required?: (values: unknown) => readonly Path[];
}
```

### `RuleIssue`

A type.

An expected failure of a rule. The first seven name the rule; `rules.too_large` and `rules.too_many_issues` are the limits of a check: - `rules.required_if`: the condition holds, and this field is blank; - `rules.all_or_none`: another field of the group is filled, and this one is blank; - `rules.at_least`, `rules.exactly`: `count` of the fields or elements count, under `minimum` or not `expected`; - `rules.mutually_exclusive`: another field of the group is filled, and so is this one; - `rules.unique`: another element of the list has the same key; - `rules.ordered`: this value comes before the value it must follow, or cannot be compared with it; - `rules.too_large`: the list has more than `maximum` elements, none of them read; - `rules.too_many_issues`: the check stopped at `maximum` errors, the last in the list, at the root.

```ts
export type RuleIssue = {
    readonly code: 'rules.required_if';
    readonly path: Path;
} | {
    readonly code: 'rules.all_or_none';
    readonly path: Path;
} | {
    readonly code: 'rules.at_least';
    readonly path: Path;
    readonly params: {
        readonly minimum: number;
        readonly count: number;
    };
} | {
    readonly code: 'rules.exactly';
    readonly path: Path;
    readonly params: {
        readonly expected: number;
        readonly count: number;
    };
} | {
    readonly code: 'rules.mutually_exclusive';
    readonly path: Path;
} | {
    readonly code: 'rules.unique';
    readonly path: Path;
} | {
    readonly code: 'rules.ordered';
    readonly path: Path;
} | {
    readonly code: 'rules.too_large';
    readonly path: Path;
    readonly params: {
        readonly maximum: number;
    };
} | {
    readonly code: 'rules.too_many_issues';
    readonly path: Path;
    readonly params: {
        readonly maximum: number;
    };
};
```

### `assertDeclaredReads`

A function.

The test of a rule: runs it on these values, notes each read, and throws if it read a value its `reads` does not declare, or wrote to them. Built-in rules hold by construction; this is for the ones an application writes, on the values of its tests. Not seen: a branch these values do not take, what a closure reads, the inside of a Date, a Map or a class instance, and a decision on a value a declared path only goes through (`values.a === 5` where `['a', 'b']` is declared). Two paths to one object are two views, so that they compare as different here.

```ts
export declare function assertDeclaredReads(rule: Rule, values: unknown): void;
```

| Contract | Value |
|---|---|
| `@pure` | yes |
| `@sharing` | none |
| `@complexity` | O(r × d) (r = reads of the rule, d = declared paths) |
| `@throws` | Error when the rule reads a value it does not declare, or writes to the values |
| `@throws` | what the rule or a getter of the values throws, unchanged |
| `@since` | 0.2 |
| `@experimental` | yes |

**Example**

```ts
assertDeclaredReads({ reads: [], targets: [], check: (values) => [values.b] && [] }, { b: 1 }) // throws
```

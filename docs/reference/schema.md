### `SchemaIssue`

A type.

An expected failure of a read: - `schema.invalid_type`: the value is not a `string`, a finite `number`, a `boolean`, an `array` or a plain `object`; - `schema.invalid_value`: the value is none of the literals or options of `expected`; - `schema.missing`: the object has no own key here, and its schema is not `optional`; - `schema.unknown_key`: the object has a key its schema does not declare, under `unknownKeys: 'reject'`; - `schema.too_short`, `schema.too_long`: the text has `length` code units, outside `minimum` or `maximum`; - `schema.too_small`, `schema.too_large`: the number or the number of elements is outside `minimum` or `maximum`; - `schema.not_integer`: the number has a fraction; - `schema.invalid_format`: the text does not match `pattern`, the source of the regular expression; - `schema.too_many_issues`: the read stopped at `maximum` issues, the last in the list, at the root.

```ts
export type SchemaIssue = {
    readonly code: 'schema.invalid_type';
    readonly path: SchemaPath;
    readonly params: {
        readonly expected: 'string' | 'number' | 'boolean' | 'array' | 'object';
    };
} | {
    readonly code: 'schema.invalid_value';
    readonly path: SchemaPath;
    readonly params: {
        readonly expected: readonly SchemaLiteral[];
    };
} | {
    readonly code: 'schema.missing';
    readonly path: SchemaPath;
} | {
    readonly code: 'schema.unknown_key';
    readonly path: SchemaPath;
} | {
    readonly code: 'schema.too_short';
    readonly path: SchemaPath;
    readonly params: {
        readonly length: number;
        readonly minimum: number;
    };
} | {
    readonly code: 'schema.too_long';
    readonly path: SchemaPath;
    readonly params: {
        readonly length: number;
        readonly maximum: number;
    };
} | {
    readonly code: 'schema.too_small';
    readonly path: SchemaPath;
    readonly params: {
        readonly minimum: number;
    };
} | {
    readonly code: 'schema.too_large';
    readonly path: SchemaPath;
    readonly params: {
        readonly maximum: number;
    };
} | {
    readonly code: 'schema.not_integer';
    readonly path: SchemaPath;
} | {
    readonly code: 'schema.too_many_issues';
    readonly path: SchemaPath;
    readonly params: {
        readonly maximum: number;
    };
} | {
    readonly code: 'schema.invalid_format';
    readonly path: SchemaPath;
    readonly params: {
        readonly pattern: string;
    };
};
```

### `array`

A function.

A schema of arrays. An array over `maxLength` gets that one issue, and no element is read. Otherwise each element is read in turn, a hole as `undefined`, and `minLength` is checked after them, so that one read reports them all. The output is a new dense array.


| Contract | Value |

### `discriminatedUnion`

A function.

A schema of objects of several forms, told apart by the literal under `key`: the option it names reads the object, and the issues are those of that option alone. An absent `key` is `schema.missing`, and a value no option names is `schema.invalid_value`, both at `key`.

```ts
export declare function discriminatedUnion<K extends string, const O extends readonly UnionOption<K>[]>(key: K, options: O): Schema<InferInput<O[number]>, InferOutput<O[number]>>;
```

| Contract | Value |
|---|---|
| `@pure` | yes |
| `@sharing` | structural |
| `@complexity` | O(n) to build (n = number of options); a read is O(1), plus the cost of the option |
| `@throws` | TypeError when an option is not a schema or has no literal under `key`, or two options have the same one |
| `@throws` | what a getter or a Proxy trap of the input throws, unchanged, when reading |
| `@since` | 0.2 |
| `@experimental` | yes |

**Example**

```ts
const pay = discriminatedUnion('by', [object({ by: literal('card') }), object({ by: literal('cash') })]);
parse(pay, { by: 'cash' }) // { ok: true, value: { by: 'cash' } }
```

### `parse`

A function.

### `withMessages`

A function.

`schema` with the application's words: the issues its `~standard` interface gives carry what `format` builds, where they would carry their code. Call it on the one schema an engine reads; the schemas it holds need nothing. The schema is not changed, and `parse` gives the same issues as before.

```ts
export declare function withMessages<S extends Schema<unknown, unknown>>(schema: S, format: IssueFormatter): S;
```

| Contract | Value |
|---|---|
| `@pure` | yes |
| `@sharing` | structural |
| `@complexity` | O(1), plus one call of `format` per issue of a read through `~standard` |
| `@throws` | TypeError when `schema` is not a schema |
| `@throws` | TypeError when `format` is not a function, or returns something else than a string, at the read |
| `@since` | 0.2 |
| `@experimental` | yes |

**Example**

```ts
withMessages(number(), (issue) => `Invalid: ${issue.code}`)
```
